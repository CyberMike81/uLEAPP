# October 21 source audit response

The supplied audit contained three actionable "fix now" rows. Its counts mention
14 findings, but the pasted text only includes those three; no additional findings
were inferred.

- Windows runs the installation pipeline off the WPF dispatcher. ReleaseClient
  and Installer do not capture the UI context; status/progress are explicitly
  marshalled back, with download progress limited to roughly ten updates/second.
- Windows Stop cancels metadata and active download body reads. Every body read
  has a 60-second idle cancellation deadline. An official installer already
  running is allowed to finish and record its result; no next app starts.
- Linux has Stop for checks, downloads and preparation before version publication.
  A bounded background reader keeps cancellation responsive during a stalled socket;
  the consumer owns file writes, so a stopped reader cannot later install a file.
  Socket timeouts plus a 60-second no-data watchdog bound stalls. Progress is
  throttled to roughly ten reports/second. Cancellation cleans staging folders and
  retains the previous selection. Atomic publication finishes without interruption.
- Mac caches app paths and icons until discovery or version changes, rather than
  reading them from the SwiftUI body. Logs batch UI publication to ten times/second,
  preserve partial UTF-8/CRLF across reads, and discard superseded CR progress lines.
  Installed-app discovery now supports Stop and a 60-second process deadline.

**Mac boundary:** active Homebrew installs still stop after the current operation.
Killing Homebrew or its installer descendants mid-install could leave an app
partially installed. uLEAPP does not own Homebrew's network stream and does not
claim immediate cancellation or a body-idle timeout for it. The UI retains its
"Stop after this operation" wording for this path. This part of the audit remains
an explicit limitation, rather than treating process termination as download
cancellation.

Regression coverage includes a blocked Linux read, idle watchdog, stopped update
cleanup, Windows body cancellation and timeout after headers, and Mac CR progress,
CRLF split across reads, and split UTF-8. The existing 79 Homebrew worker tests
continue to cover stop-at-boundary behavior. Windows x64 runs packaged checks in CI;
ARM64 is compiled there but still needs a native Windows ARM runtime check.

These are source changes for review. Published binaries and release downloads are
not replaced as part of this audit response.
